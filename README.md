# Сводка диапазона / Range Summary

Клиентское расширение для **SillyTavern 1.19.0 и новее**. Никаких серверных
плагинов, сборки, npm-зависимостей или отдельных API-ключей расширению не нужно.
Запросы идут через текущее подключение SillyTavern.

**Начало → Конец → Сводка → готовый служебный комментарий в чате → исходники
до выбранного конца исключены из контекста.** Сам комментарий со сводкой тоже
исключён из контекста. Скопируйте его в Lorebook самостоятельно.

В версии **1.0.1** действия перенесены в штатное меню **«…»** сообщения.
Три компактных значка: флаг — **Начало**, клетчатый флаг — **Конец**,
лист — **Сводка**. Названия доступны в подсказках и для экранного диктора.
Отдельной строки кнопок под сообщением больше нет.

В **1.0.2** используются оригинальные SVG из согласованного набора: флаг со
стрелкой начала, клетчатый флаг со стоп-отметкой и лист с искрой для сводки.
Значки размером 18px встроены в расширение, не требуют загрузки шрифтов или
отдельных файлов и наследуют цвет текущей темы. Размеры областей нажатия сохранены.

В **1.0.3** значки повторяют новый референс: закладка с плюсом — **Начало**,
закладка с галочкой — **Конец**, свиток — **Сводка**, два листа — **Копировать**.
Под каждой сводкой есть постоянно видимая кнопка **Копировать**; выделять текст
пальцем не требуется. Копирование также доступно в меню «…» самой сводки.
В буфер попадает весь исходный текст результата с Markdown, датами и переносами,
без добавленного расширением заголовка с диапазоном. После нажатия появляется
«Скопировано». Работает и для сводок, созданных предыдущими версиями расширения.

Для буфера обмена используется Clipboard API, при его отсутствии или отказе —
резервный способ `execCommand('copy')` с временным невидимым полем. Если браузер
блокирует оба способа, кнопка показывает ошибку, а не ложное подтверждение.
Успешная работа проверена в Chromium; физический Safari требует проверки отдельно.

## Установка по Git-ссылке

Готовый репозиторий: **https://github.com/PavelSkellig/SillyTavern-Range-Summary**.
Для установки откройте в SillyTavern «Расширения → Установить расширение»,
вставьте эту ссылку и перезагрузите страницу.

### 1. Создать GitHub-репозиторий

1. Войдите в GitHub и выберите **New repository**.
2. Назовите его, например, `SillyTavern-Range-Summary`, выберите **Public**.
3. Нажмите **Create repository**.
4. Через **uploading an existing file** / **Add file → Upload files** загрузите
   в корень репозитория `manifest.json`, `index.js`, `style.css`, `README.md`
   и `LICENSE`. Файлы не должны лежать внутри дополнительной папки.
5. Нажмите **Commit changes**. Скопируйте HTTPS-ссылку репозитория вида
   `https://github.com/ВАШ_ЛОГИН/SillyTavern-Range-Summary`.

Альтернатива для терминала в папке проекта:

```sh
git init
git add manifest.json index.js style.css README.md LICENSE
git commit -m "Add Range Summary extension"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/SillyTavern-Range-Summary.git
git push -u origin main
```

Подставьте свой логин. Создание/публикация репозитория и авторизация GitHub
выполняются вами; этот проект сам ничего не публикует.

### 2. Установить в SillyTavern

1. Обновите SillyTavern до 1.19.0 или новее.
2. Откройте **Extensions / Расширения → Install extension / Установить расширение**.
3. Вставьте HTTPS Git-ссылку репозитория и подтвердите установку.
4. Перезагрузите страницу SillyTavern.
5. В настройках расширений откройте **Сводка диапазона** и вставьте свой промпт.

При установке с iPhone расширение устанавливается на сервер SillyTavern.
Откройте обычный адрес этого сервера в Safari; отдельная установка файлов
на телефон не требуется. На сервере должны быть разрешены сторонние расширения
и установлен Git. Если пункта установки нет, это настройка сервера/прав доступа.

### Локальная установка без GitHub

Распакуйте пять указанных файлов в отдельную папку, например:

```text
SillyTavern/data/default-user/extensions/Range-Summary/
    manifest.json
    index.js
    style.css
    README.md
    LICENSE
```

В многопользовательской установке замените `default-user` на нужный профиль.
Для установки всем пользователям можно использовать
`SillyTavern/public/scripts/extensions/third-party/Range-Summary/`.
После этого перезагрузите страницу.

## Использование

1. Откройте сохранённый чат с персонажем или группой и подключите модель.
2. В настройках расширения вставьте **свой** текст в «Промпт для сводки».
   Поле по умолчанию пустое. Содержимое сохраняется глобально в профиле ST.
3. Откройте **«…»** нужного сообщения и нажмите значок флага **Начало**.
4. Откройте **«…»** другого сообщения и нажмите клетчатый флаг **Конец**. Обе границы включаются.
   Номера `#` соответствуют индексам SillyTavern, начиная с **0**.
5. В меню **«…»** любого сообщения нажмите значок листа **Сводка**. Действие использует выбранные границы,
   а не позицию сообщения, на котором её нажали.
6. Дождитесь завершения. В конце чата появится служебное сообщение **Сводка**
   с указанием диапазона. Нажмите **Копировать** прямо под текстом: результат
   окажется в буфере обмена. Окна с результатом не открываются.
7. Перенесите текст в Lorebook вручную и продолжайте игру.

Начало и конец можно менять повторным нажатием. Границы подсвечиваются;
выбранный диапазон сохраняется отдельно в метаданных каждого чата. Подгруженные
при прокрутке сообщения тоже получают три кнопки. Промпт не переписывается,
не сокращается, не дополняется инструкциями для саммаризации; макросы внутри
промпта и исходного текста передаются **буквально**, включая `{{char}}`/`{{user}}`.

До завершения операции обычная отправка блокируется штатным состоянием
генерации ST, чтобы два запроса не пересекались. Поле ввода вашей ролевой реплики
не очищается. Расширение не вызывает `Generate`, `/trigger`, автопродолжение
или события получения ролевой реплики.

## Что скрывается

Например, выбран диапазон **#100–#200**, а после него есть сообщения до #250:

- В запрос для сводки попадут **только #100–#200**.
- После успешного сохранения сводки будут исключены из контекста **#0–#200**.
- **#201–#250** останутся в прежнем состоянии.
- Новая сводка сохранится с `is_system: true` и `extra.type: "comment"`.
- Ни один оригинальный текст не удаляется и не заменяется.

Это штатное скрытие ST (`hideChatMessageRange`), а не CSS или удаление элементов.
Историю можно прокручивать и перечитывать. Тема или пользовательская настройка
самого ST может отдельно менять видимость/оформление исключённых сообщений.
Служебная отметка сводки не делает её системной инструкцией модели:
в терминологии ST `is_system` означает исключение из обычной истории генерации.

Кнопка **Восстановить скрытые исходники** возвращает в контекст только сообщения,
которые это расширение ранее скрывало из активного состояния. Уже скрытые вами
сообщения и существовавшие служебные комментарии остаются исключёнными.
**Сводки восстановление никогда не активирует.** Отключение/удаление расширения
само не восстанавливает сообщения: при необходимости восстановите их заранее
или используйте штатное `/unhide` только для нужных исходников.

## Длинная история

Сначала считываются лимит контекста и длина ответа из текущих настроек ST.
Под промпт, ответ, оформление и погрешность токенизации резервируется место.
Остальной текст последовательно делится по измеренному числу токенов, по
возможности на границах строк. Даже одно огромное сообщение обрабатывается
частями; символы Unicode не теряются. Имена, роли и исходные метки отправки
указываются рядом с текстом. Метка отправки — техническая дата ST, а не
придуманная дата события внутри сюжета. Вложения/изображения не анализируются;
сводка относится к сохранённому текстовому полю `mes` сообщений.

Каждая часть отправляется с **тем же неизменным пользовательским промптом**.
Все части проходят в исходном порядке. Ответы соединяются разделителем `---`
в **одно** сообщение. Промежуточные сообщения в чат не добавляются, повторной
суммаризации ответов моделью нет. Структура вашего промпта может повториться
в каждом ответе; связи между частями модель не видит. Это согласованный способ
обработки без дополнительного промпта объединения и без накопительной памяти.

Если промпт сам занимает контекст, будет явная ошибка. При ответе с причиной
завершения `length` / `max_tokens` сводка не фиксируется, исходники остаются
активны. Увеличьте длину ответа в основных настройках ST и повторите.
Некоторые API не сообщают причину завершения — тогда достоверно определить
обрезание ответа нельзя. Размер окна/резерв берётся из ваших настроек:
автоматически узнать истинные ограничения любого прокси невозможно.

Расширение гарантирует передачу всего выбранного **текста** без собственной
обрезки, но не может гарантировать, что модель сохранит каждую дату, факт
или требование промпта. Проверьте сводку перед переносом в Lorebook.

## Ошибки и повторные нажатия

- Ошибка генерации, пустой ответ или изменение исходников во время запроса:
  исходники не скрываются.
- После добавления сводки выполняются штатное сохранение и повторное чтение
  серверной копии. Проверяются текст сводки, исключение из контекста и исходники.
  Только после этого выполняется скрытие префикса истории.
- Во время работы допускается одна операция. Для готовых сводок хранится
  отпечаток диапазона и промпта. Повторное нажатие использует уже созданный
  результат, включая повтор после сбоя сохранения, и не создаёт дубль.
- Если вы восстановили исходники, повторное нажатие с тем же диапазоном и
  промптом использует готовую сводку и снова скрывает исходники.
- Если вы удалили сводку или изменили промпт/исходный текст, возможна новая
  генерация. Отпечаток не является защитой от действий в двух разных браузерах.
- При сбое фиксации скрытия локальные изменения откатываются и предпринимается
  сохранение отката. При полной потере сети подтвердить состояние диска нельзя:
  восстановите соединение и проверьте историю. Расширение никогда не использует
  принудительное сохранение `force` для обхода защиты целостности ST.
- Переключение чата, перестановка/изменение исходников или смена подключения
  отменяют фиксацию результата. Не переключайте чаты во время создания сводки.
  При отмене/переключении уже начатый запрос может ещё выполняться на провайдере;
  результат не будет записан в другой чат.

## Реальные API и совместимость

Проверено по исходникам официальной ветки **release**, скачанным 19 октября
2026 года (`package.json`: **1.19.0**):

| Задача | Реальный механизм |
| --- | --- |
| История | `SillyTavern.getContext().chat` |
| Отдельный запрос | `context.generateRawData({ api, prompt, instructOverride, quietToLoud })` |
| Буквальный текст | Собственный nonce запроса и события `CHAT_COMPLETION_PROMPT_READY` / `GENERATE_AFTER_COMBINE_PROMPTS`, после встроенной подстановки макросов |
| Ответ | `extractMessageFromData` из `/script.js`, без очистки/переписывания полученного текста |
| Добавление | `chat.push(message)` + `context.addOneMessage(message)` |
| Исключение | `hideChatMessageRange` из `/scripts/chats.js`; для сводки `is_system: true` с момента создания |
| Сохранение | `context.saveChat()`; подтверждение через `/api/chats/get` или `/api/chats/group/get` |
| Настройки | `context.extensionSettings` + `saveSettingsDebounced()` |
| Состояние чата | `chatMetadata`, ID в `message.extra`, `saveMetadata()` |
| Смена чата | `CHAT_CHANGED` и повторная проверка идентичности перед записью |
| Действия в меню «…» | `.mes[mesid] .extraMesButtons`, делегированный обработчик и `MutationObserver` |

Источники:
[API контекста](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/st-context.js),
[генерация и сохранение](https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js),
[штатное скрытие](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/chats.js),
[руководство расширений](https://docs.sillytavern.app/for-contributors/writing-extensions/).

Поддерживаются проверенные ветви API `openai` (режим Chat Completion, включая
его провайдеров), `textgenerationwebui`, `kobold`, `koboldhorde`, `novel`.
Способ оформления ролей и служебные обёртки транспорта определяет выбранный
провайдер. Для Text Completion передаётся буквальный промпт и текст истории,
без шаблона ролевого продолжения. Модель должна уметь выполнять такие инструкции.

Внутренние импорты необходимы: контекст не экспортирует штатную функцию скрытия,
доступ к состоянию блокировки и извлечение сырого ответа. При изменениях API
или DOM будущих версий ST может понадобиться обновление расширения. Другие
расширения, меняющие готовые промпты, прокси и настройки провайдера могут влиять
на итоговый запрос; протестируйте их совместимость отдельно. Скрытие штатной
истории не запрещает другим расширениям самостоятельно читать её или записывать
в собственную память. Сам Range Summary такой памяти и записи в Lorebook не имеет.

## Проверки проекта

```sh
npm test
npm run check
```

Node.js 20+ нужен **только для тестов**, не для установки расширения. Автотесты
проверяют диапазоны, Unicode, все части длинной истории, буквальность запросов,
откаты, сохранение перед скрытием, дубли, переключение чатов, смену модели,
восстановление и повторное скрытие после восстановления.

Дополнительный `tests/browser-smoke.cjs` использует Playwright и установленный
Edge. Проверен полный интерфейсный сценарий с тестовым хостом на ширинах
320/390/1280 px, светлые/тёмные цвета, скрытие действий до открытия штатного
меню «…», компактные значки с сенсорными областями 36 px, подгрузка сообщений
и сохранение настроек после перезагрузки.
Это не тест настоящего сервера/провайдера модели. Физический iPhone/Safari
и живое подключение SillyTavern в среде разработки не были доступны.

Рекомендуемая проверка после установки: в тестовом чате выбрать #1–#2 из
четырёх сообщений, получить сводку, проверить исключение #0–#2 и самой сводки,
активность #3; затем восстановить исходники и убедиться, что сводка по-прежнему
исключена. Перед первым использованием на важной истории экспортируйте чат
штатными средствами SillyTavern.
